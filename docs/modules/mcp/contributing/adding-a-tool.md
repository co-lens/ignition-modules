# Adding a tool

One constructor call, a hand-written schema, no annotations or codegen:

```kotlin
Tool(
    name = "list_tag_providers",
    title = "List tag providers",
    description = "Lists the tag providers configured on this gateway.",
    inputSchema = schema { string("filter", "Substring to match") },
    readOnly = true,          // false puts it behind the write-scoped endpoint only
    handler = { args ->
        jsonObject { put("providers", jsonArrayOfStrings(context.tagManager.tagProviderNames)) }
    },
)
```

Throwing from a handler is fine and often right: `McpServer` turns it into an `isError` tool result
rather than a protocol error, so the model sees the message and can correct its call.

## Keep construction context-free

Everything a tool needs from the Ignition context belongs **inside the handler lambda**, not in a
field computed at construction time.

That isn't only style. The [tool reference](../tools/index.md) is generated by constructing the
real tool classes against a stub context and reading their metadata — which works precisely because
no tool touches its context until a handler runs. The generator records any context call made
during construction and fails the build with the method name, so if you break this you'll be told
immediately rather than shipping quietly wrong documentation.

If you genuinely need a context-derived value at construction, make it `by lazy` or wrap it in a
lambda, as `PerspectiveTools` does with the Perspective registry.

## Then regenerate the reference

```bash
./gradlew :tools:tool-docs:generateToolDocs
```

and commit `docs/src/data/tools.json`. A new tool documents itself — name, description, arguments,
and the read-only/destructive badges all come from the declaration above. CI regenerates and fails
on a diff, so a stale reference can't merge.

One gap that gate can't close: if you add a whole new tool *class*, register it in the hook **and**
in `tools/tool-docs/src/main/kotlin/io/colens/tooldocs/Main.kt`. The diff check compares the
generator's output against itself, so a class that was never listed looks perfectly consistent.
